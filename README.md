# Debian 13 极简 1G qcow2 镜像

基于 **[@梦影](https://www.nodeseek.com/space/34503#/general)**（[改了下 Bin 佬的 dd 脚本，支持 btrfs 文件系统](https://www.nodeseek.com/post-480914-1)）的 dd 镜像为底包制作的极简 qcow2 镜像，裁剪掉一切不必要的东西，文件约 264MB，挂上就能跑。

---

## 镜像规格

| 项目 | 值 |
|------|-----|
| 系统版本 | Debian 13 trixie |
| 内核 | 6.12 |
| 文件系统 | btrfs（zstd:3 压缩） |
| qcow2 文件大小 | ~264 MB |
| 虚拟磁盘容量 | 1 GiB |
| 首次启动后可用空间 | ~650 MB |
| 引导方式 | BIOS（传统），GRUB i386-pc |
| root 密码 | `nodeseekdebian13js` |

## 注意事项

> **⚠️ root 密码**：默认密码为 `nodeseekdebian13js`，请在首次登录后立即执行 `passwd` 修改密码，切勿在生产环境中继续使用默认密码。

> **首次启动扩容**：启动后 btrfs balance 需要约 1~3 分钟完成，这段时间内 `df -h` 显示的可用空间偏小属正常现象，稍等即可恢复正确值。

## 面向新人的仓库导读

这个仓库目前是一个**单文件文档型仓库**，核心目标是发布和说明一个「Debian 13 极简 1G qcow2 镜像」。

### 1) 整体结构是什么？

当前目录结构非常简单：

- `README.md`：仓库唯一核心文件，包含镜像定位、参数、下载入口、注意事项与已验证环境。
- `Releases`（GitHub 页面，不在仓库文件树中）：实际镜像二进制产物的分发渠道。

也就是说，这个仓库现阶段不是“源码构建型项目”，而是“**镜像发布说明型项目**”。

### 2) 新人需要优先了解哪些内容？

建议按下面顺序阅读并理解：

1. **镜像规格**  
   明确系统版本、内核、文件系统（btrfs + zstd）、镜像体积和引导方式（BIOS/GRUB i386-pc），这是后续排障和兼容性判断的基础。

2. **安全事项（root 默认密码）**  
   这是生产可用性的红线：首次登录后必须立刻修改 root 密码。

3. **首次启动扩容行为**  
   了解 btrfs balance 的时间窗口，避免把“短时间可用空间偏小”误判为镜像异常。

4. **验证环境**  
   当前主要验证场景为“阿里云导入自定义镜像直接启动”，新人在迁移到其他平台时应做补充验证。

### 3) 后续学习建议

如果你要继续维护或扩展这个仓库，推荐按三条线并行：

- **A. 镜像运行与文件系统基础**
  - 学 btrfs 常用命令：`btrfs filesystem usage`、`btrfs balance status`、`btrfs scrub`。
  - 理解 qcow2 体积、虚拟磁盘容量、来宾文件系统可用空间三者关系。

- **B. 启动链路与兼容性**
  - 了解 BIOS + GRUB i386-pc 启动流程。
  - 若计划适配更多云厂商，补充 UEFI 场景验证并记录差异。

- **C. 仓库演进与文档规范**
  - 建议后续补充 `CHANGELOG.md`（版本差异）和 `docs/`（导入步骤、常见故障、平台兼容矩阵）。
  - 若未来公开构建流程，可新增 `scripts/` 保存镜像裁剪/打包脚本，把“可复现构建”沉淀下来。
